# Project Essay Intake

Use this sequence to turn an adopter's free-form project description into
evidence-backed context.

## 1. Accept free-form input

Invite the adopter to describe repositories, ownership, responsibilities,
dependencies, local setup and run commands, CI/CD, deployment, observability,
environments, authentication boundaries, and known constraints in any order.
Do not require a form before accepting the essay.

## 2. Extract claims

Split the essay into discrete claims about paths, people or teams, systems,
commands, relationships, and operational boundaries. Preserve the source
passage for each claim and do not add facts that were not supplied.

## 3. Classify evidence

For every claim, classify it as **verified**, **assumed**, **unknown**, or
**contradictory**. Link verified claims to evidence and record confidence,
freshness, and authority. Keep assumptions explicit until checked; preserve
contradictions rather than choosing a side; record unknowns without guessing.

## 4. List gaps

Compare the claims with the project-context template. List missing ownership,
paths, commands, dependencies, deployment relationships, observability,
authentication boundaries, and evidence needed for safe work.

## 5. Ask one targeted question at a time

Ask only the single highest-value question needed to resolve the next gap or
contradiction. Wait for the answer, update the classifications, and then ask
the next question. Do not present a batch questionnaire or silently infer an
answer.
