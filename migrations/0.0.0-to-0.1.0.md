# Migration 0.0.0 to 0.1.0

This migration converts the old OpenCode-only starter layout into the neutral
0.1.0 distribution. It is applicable only when the installed manifest release
is `v0.0.0` (or when an explicitly approved legacy migration has no manifest).
It must be run through `playbooks/upgrade.md`, not by copying files by hand.

## Scope and affected paths

Create a pre-migration copy of every affected path and a durable migration
record before writing. The affected set includes the old root `AGENTS.md`,
OpenCode-specific `.opencode/` instructions/configuration/skills, any legacy
skill locations, and the new distribution paths:

* rewrite the root AGENTS policy (`AGENTS.md`) as the client-neutral bootstrap
  and upgrade policy;
* add the one-line `CLAUDE.md` shim pointing to `@AGENTS.md`;
* relocate portable skills to canonical `.agents/skills/<skill>` and preserve
  only selected, clean managed links/outputs;
* extract OpenCode-specific behavior into `adapters/opencode/` rather than
  retaining it in portable core files;
* add `VERSION`, `CHANGELOG.md`, `playbooks/bootstrap.md`, and
  `playbooks/upgrade.md` release metadata and procedures;
* introduce `.agent-template/manifest.yaml` with release, selected clients and
  modules, owners, hashes/link targets, update policies, warnings, and applied
  migrations.

The neutral distribution also places shared instructions, roles, project
context, and validation under `core/`, and keeps client translations under
`adapters/`. Do not claim that an unselected adapter or capability was
materialized.

## Safety checks

Read ordinary repository metadata and the legacy layout only; never inspect
cached credentials, token stores, private keys, or secret values. Inventory
each affected path and classify it as clean managed, modified, missing, or
unmanaged. The old OpenCode files have no ownership unless a trusted legacy
record proves otherwise: never silently adopt or overwrite them. Preserve
unmanaged files and local changes, and stop for conflicts. Authentication stays
human-controlled; any required authenticated client check is blocked until the
human performs authentication in their own session.

Require explicit selection of clients and modules. The OpenCode adapter is
selected only when requested; Claude, Codex, and Antigravity are not inferred
from detected files. Apply the five manifest policies exactly: clean generated
files use `replace-if-unmodified`, clean links use
`replace-link-if-unmodified`, reviewed portable-content changes use `merge`,
`user-owned` paths are preserved, and obsolete clean legacy outputs use
`remove-if-unmodified`.

## Migration and validation commands

After approval, take the pre-migration copy, perform the root rewrite and
neutral relocation in the ordered plan, then generate only selected adapter
outputs. Follow `core/validation/ACCEPTANCE.md` and the selected adapters'
offline validation guidance. Record each check as passed, failed, skipped, or
blocked with its evidence and result.

Verify that `.agents/skills` files are portable, OpenCode-only references
are confined to the adapter, relative links resolve, generated content hashes
match the proposed manifest, the manifest schema is valid, and no unmanaged or
modified path was overwritten. Live client diagnostics are optional and may be
reported as skipped; a required unavailable or unauthenticated check is
blocked, not passed. Update release, hashes, warnings, and applied migration
history only after required validation succeeds.

## Rollback

If a safety check, approval, write, or validation fails, stop and produce a
rollback report. Restore the complete pre-migration copy, including the old
root policy, legacy skill locations, OpenCode files, and metadata, then verify
that the pre-migration hashes and links are restored. Do not restore over a
newly modified or unmanaged path without explicit conflict resolution. Remove
or mark the incomplete manifest/run record so it cannot claim success.

Rollback is specifically defined as restoring the pre-migration copy, not as
reconstructing the old OpenCode-only layout from memory. Preserve the copy and
the report until the user confirms the migration is complete or the rollback
has been accepted.
